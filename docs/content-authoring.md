# Content authoring

Use a stable route ID and a short page description that describes the action a student can take. Each course lesson belongs to one of the twelve module records in `content/course.mjs`; keep four core lessons per module. Include prerequisites, a worked numerical example, a realistic exercise, a verification prompt and primary sources. Add links to a relevant interactive lab or Java recipe when appropriate.

Use a shared coordinate and units contract for each example. State the origin, axis directions, angle reference and measurement time. Keep SDK method names and project source links consistent with the selected SDK. Use specific result status language such as compile-checked, synthetic-input checked or hardware-checked.

To add a season, save the controlling manual revision and source URLs, record inspected sections and use a dedicated section with its own application links. Verify sizes and geometry before committing constants. Keep practice targets and surveyed coordinates explicitly labeled as fixture values.

Run `npm test` and open the affected deep routes. Tests verify inventory and local links. Verify new external references directly before publishing.
